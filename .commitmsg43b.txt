VirtualQueryEx on the LIVE client proved the truth: 0xD1AC736B, 0xB450EDDC
and 0xD3C00E14 are all MEM_FREE (unmapped) — NOT uncommitted-BSS — and the
resolver's GUID pointer address is SESSION-DEPENDENT. A static page commit
can never cover it. (0xD3C00E14 works only because SafeNativeCast commits
that exact free address and writes the GUID there each session.)

Fix: the crash shield in main.cpp now VirtualAlloc-commits the FAULTING page
on the first 0x512B07/0x512B0A AV per address (guarded to 0x10000..
0x7FFF0000; VirtualAlloc failure is harmless — the register substitution
still recovers). Every later dispatch to that address reads valid zero-filled
memory (ObjectPtr(0,0,8)=0 -> walk skips) with NO AV and NO shield
involvement — ~800 recovered AVs/session becomes ONE per unique address.
