feat(addon): "Auto Search" toggle for the Auto Attack condition + reliable distance/facing basic-check gates

User: "the target distance, and target facing basic checks seem to be
inconsistent and allowing some casts that shouldnt be allowed. additionally the
aura search is still extremely slow and inconsistent. and the rotation is
locking up. i want an additional toggle for the auto attack condition. call it
'Auto Search': when toggled, look for mobs within auto attack range, and with
the 'not' invert toggle enabled, auto attack is cast on the current target OR a
nearby applicable target when not currently autoing."

NEW FEATURE - "Auto Search":
- Conditions.lua `auto_repeat` gains a bool `auto_search` param (Editor
  checkbox). With Invert ON ("not autoing") the Auto Attack slot engages the
  current target OR the nearest hostile within auto-attack range.
- Engine.lua slot_target_policy: an auto_search slot becomes "optional" so it
  is reachable with NO client target.
- World.lua find_auto_attack_target(range): parses the runtime NearbyHostiles
  pack (n|0xGUID:entry:x:y:z:center:edge:flags:hp:mhp:face), closest alive
  hostile with center<=range, not blacklisted, 100ms cache. Parser unit-tested
  against a realistic pack.
- Executor.lua auto-attack branch: reads auto_search/invert from the slot
  conditions; with no usable current target, engages the nearest hostile
  (6.0yd) via A.AttackEngage(guid) - a ZERO-selection-touch engage, so
  acquire-off is preserved (client target/unitframe never changed). The
  "already autoing" gate uses the client IsAttacking flag (attacking anything
  = skip).

FIX - distance/facing basic-check inconsistency:
- FACING: re-added the gate but ONLY on a CONFIDENT not-facing
  (World.is_facing_guid == false) in BOTH the try_list candidate path and the
  target-relative path. The runtime now rejects |f|<0.0001 as UNDETERMINED
  (ObjectIsFacing -> nil -> wire), so this can never reproduce the round-40
  lockup, and it stops the "target needs to be in front of you" red spam the
  user reported. Undetermined always wires (client is the final authority).
- DISTANCE: the per-candidate range gate NEVER wires a candidate with an
  unknown/unplaceable distance (nil/0/>=999) when the spell max range is known
  (last_why="oor_unknown" -> next candidate). Only measured center is compared
  to the spell's real max range, no tolerance. Spell-max-unknown stays
  fail-open (round-38 decision).

AURA SEARCH / LOCKUP: runtime AuraSearch cache already 50ms; Lua 50ms; the
long "wait cooldown" holds are mostly real (all melee abilities on 6s CDs +
no new dot targets). Auto Search + the 0x-prefix/latch fixes address the
perceived lockup. Needs a live example if it persists.

Addon-only (no runtime rebuild). Deployed (197 files); /reload to pick up.
